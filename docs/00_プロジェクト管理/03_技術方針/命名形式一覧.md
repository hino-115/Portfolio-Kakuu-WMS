# 命名形式一覧

## 1. 目的

本資料は、KAKUU WMSの開発において参照する命名形式の特徴、記述方法、使用例を整理したものである。

本資料は命名形式の説明を目的とし、すべての命名形式をKAKUU WMSで採用するものではない。

実装時に使用する命名規則については、別資料の `コーディング規約.md` に従う。

## 2. 命名形式一覧

各形式の違いを比較できるように、原則として以下の3単語を使用する。

- `item`：商品
- `stock`：在庫
- `quantity`：数量

| No. | 命名形式 | 記述例 |
|---|---|---|
| 1 | lowerCamelCase | `itemStockQuantity` |
| 2 | UpperCamelCase / PascalCase | `ItemStockQuantity` |
| 3 | lower_snake_case | `item_stock_quantity` |
| 4 | UPPER_SNAKE_CASE / SCREAMING_SNAKE_CASE | `ITEM_STOCK_QUANTITY` |
| 5 | kebab-case | `item-stock-quantity` |
| 6 | flatcase | `itemstockquantity` |
| 7 | Train-Case | `Item-Stock-Quantity` |
| 8 | COBOL-CASE | `ITEM-STOCK-QUANTITY` |
| 9 | path/case | `item/stock/quantity` |
| 10 | dot.case | `item.stock.quantity` |
| 11 | Hungarian Notation | `intItemStockQuantity` |

## 3. 命名形式の詳細

### 3.1 ローワーキャメルケース（lowerCamelCase）

**変換ルール**

- 最初の単語の先頭を小文字にする。
- 2単語目以降の先頭を大文字にする。
- 単語間に区切り文字を使用しない。

**記述例**

`itemStockQuantity`

**一般的な用途**

JavaやJavaScriptなどの変数名、メソッド名に使用される。

**注意点**

単語の境界を大文字で表現するため、単語をすべて小文字にすると区切りが分かりにくくなる。

**類似形式との違い**

UpperCamelCaseとの違いは、最初の単語の先頭が小文字になる点である。

### 3.2 アッパーキャメルケース（UpperCamelCase / PascalCase）

**変換ルール**

- すべての単語の先頭を大文字にする。
- 単語間に区切り文字を使用しない。

**記述例**

`ItemStockQuantity`

**一般的な用途**

Javaなどのクラス名、インターフェース名に使用される。

**注意点**

lowerCamelCaseと混同しないよう、先頭文字の大文字・小文字を統一する。

**類似形式との違い**

lowerCamelCaseとは異なり、最初の単語も大文字で始める。

### 3.3 ローワースネークケース（lower_snake_case）

**変換ルール**

- すべての単語を小文字にする。
- 単語間をアンダースコア `_` で区切る。

**記述例**

`item_stock_quantity`

**一般的な用途**

SQLのテーブル名、カラム名や、Pythonの変数名などに使用される。

**注意点**

単語間の区切りにはアンダースコアを使用し、ハイフンと混同しない。

**類似形式との違い**

UPPER_SNAKE_CASEとはアルファベットの大文字・小文字が異なる。

### 3.4 アッパースネークケース（UPPER_SNAKE_CASE / SCREAMING_SNAKE_CASE）

**変換ルール**

- すべての単語を大文字にする。
- 単語間をアンダースコア `_` で区切る。

**記述例**

`ITEM_STOCK_QUANTITY`

**一般的な用途**

Javaなどで定数名に使用される。

**注意点**

通常の変数名と区別するために使用されることが多いが、大文字であること自体が値の変更を禁止するわけではない。

**類似形式との違い**

lower_snake_caseと区切り文字は同じだが、すべて大文字で記述する。

### 3.5 ケバブケース（kebab-case）

**変換ルール**

- すべての単語を小文字にする。
- 単語間をハイフン `-` で区切る。

**記述例**

`item-stock-quantity`

**一般的な用途**

HTMLの属性名、CSSのクラス名、ファイル名などに使用される。

**注意点**

Javaなどではハイフンが減算演算子として扱われるため、通常の変数名には使用できない。

**類似形式との違い**

lower_snake_caseとは区切り文字が異なる。

### 3.6 フラットケース（flatcase）

**変換ルール**

- すべての単語を小文字にする。
- 単語間に区切り文字を使用しない。

**記述例**

`itemstockquantity`

**一般的な用途**

短い識別子や、区切り文字を使用しない命名が求められる場面で見られる。

**注意点**

単語の境界が分かりにくいため、長い名称には適さない場合がある。

**類似形式との違い**

lowerCamelCaseとは異なり、単語の先頭を大文字にしない。

### 3.7 トレインケース（Train-Case）

**変換ルール**

- すべての単語の先頭を大文字にする。
- 単語間をハイフン `-` で区切る。

**記述例**

`Item-Stock-Quantity`

**一般的な用途**

見出しや名称など、単語の区切りを明示する表記に使用されることがある。

**注意点**

プログラミング言語の識別子としては使用できない場合がある。

**類似形式との違い**

kebab-caseとは各単語の先頭が大文字になる点が異なる。

### 3.8 COBOLケース（COBOL-CASE）

**変換ルール**

- すべての単語を大文字にする。
- 単語間をハイフン `-` で区切る。

**記述例**

`ITEM-STOCK-QUANTITY`

**一般的な用途**

COBOLの識別子などで見られる形式である。

**注意点**

名称にハイフンを含むため、Javaなどの変数名には使用できない。

**類似形式との違い**

Train-Caseとは異なり、すべての文字を大文字にする。

### 3.9 パスケース（path/case）

**変換ルール**

- すべての単語を小文字にする。
- 単語間をスラッシュ `/` で区切る。

**記述例**

`item/stock/quantity`

**一般的な用途**

URLのパスやディレクトリ構造の表現などに使用される。

**注意点**

スラッシュはパスの階層区切りとして扱われるため、単一のファイル名や変数名として使用する形式ではない。

**類似形式との違い**

kebab-caseやdot.caseとは区切り文字が異なり、階層を表現する用途に適している。

### 3.10 ドットケース（dot.case）

**変換ルール**

- すべての単語を小文字にする。
- 単語間をピリオド `.` で区切る。

**記述例**

`item.stock.quantity`

**一般的な用途**

設定項目のキーや、階層的な名称の表現などに使用される。

**注意点**

Javaなどではピリオドがメンバーアクセスなどに使用されるため、単一の変数名には使用できない。

**類似形式との違い**

lower_snake_caseやkebab-caseとは区切り文字が異なる。

### 3.11 ハンガリアン記法（Hungarian Notation）

**変換ルール**

- 変数名の先頭に、型や用途などを表す接頭辞を付ける。
- 接頭辞の具体的な形式は、採用する規則によって異なる。

**記述例**

`intItemStockQuantity`

上記は、整数型であることを示す接頭辞を付けた説明用の例である。

**一般的な用途**

変数の型や役割を名前から識別するために使用される。

**注意点**

型を表す接頭辞は、変数の型を変更した場合に名称と実態が一致しなくなる可能性がある。

また、ハンガリアン記法には型を表す方式と、意味・用途を表す方式がある。

**類似形式との違い**

他の命名形式が主に単語の区切り方や大文字・小文字の使い分けを定めるのに対し、ハンガリアン記法は接頭辞によって情報を付加する命名方式である。

そのため、lowerCamelCaseなどと組み合わせて使用することもできる。
