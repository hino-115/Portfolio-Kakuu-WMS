# 技術方針

## 目的

本資料は、KAKUU WMSの開発で使用する技術および開発上の基本方針を整理し、技術選定の根拠を明確にすることを目的とする。

採用する言語、フレームワーク、データベース、開発ツール等について、単に使用技術を列挙するだけでなく、システムの規模やポートフォリオとしての目的を踏まえた選定理由を記録する。

また、実装時の判断に一貫性を持たせるため、本フォルダ内の `技術選定.md` および `コーディング規約.md` とあわせて参照する。

## 技術選定

### Java

Javaは、直近で学習した内容を復習しながら、実際のシステム開発を通して理解を定着させることを目的として採用した。

文法やオブジェクト指向、クラス設計など、学習した内容を実装の中で確認しながら進めることで、知識だけでなく実践的な理解につなげることを重視した。

### MySQL

MySQLについても、直近で学習したSQLやデータベース設計の内容を復習しながら活用することを目的として採用した。

テーブル設計、SQLによるデータ操作、Javaからのデータベース接続などを実際のシステム開発の中で経験し、学習した内容を定着させることを重視した。

### Spring Boot

JavaでWebアプリケーションを開発するためのフレームワークとして、Spring Bootを採用した。

JavaのWeb開発で広く利用されており、データベースとの連携方法に関する情報や事例も多いため、学習しながら開発を進めやすいと判断した。

また、今回使用するMySQLやSpring JDBCとの組み合わせについても一般的であり、KAKUU WMSの構成に適していると考えた。

### Spring JDBC

データベース接続にはSpring JDBCを採用した。

JDBCを直接使用する場合は、データベース接続やSQL実行、結果取得、リソースのクローズ処理など、多くの定型的なコードを記述する必要がある。

Spring JDBCを利用することで、これらの処理を簡略化でき、コードをより簡潔に保つことができる。また、リソース管理などをフレームワーク側に任せることで、実装上のミスを減らしやすいと考えた。

一方で、SQL自体は自分で記述するため、SQLを直接確認しながら実装できる点も今回の学習目的に適していると判断した。

### Spring MVC

Webアプリケーションを開発するうえで、基本的な設計パターンの一つであるMVCを理解し、実装に取り入れることを目的としてSpring MVCを採用した。

Spring MVCを利用することで、Model・View・Controllerの役割を分けた構成を無理なく実装でき、処理の責務を整理しながらWebアプリケーションを構築できると考えた。

また、今回採用するJSPをViewとして扱う構成とも相性がよく、MVCの考え方を実装を通して確認しやすい点も採用理由とした。

### JSP

画面表示にはJSPを採用した。

JSPはHTMLをベースに、Java側で処理したデータを画面へ埋め込んで表示できるため、動的なWeb画面を構築しやすいと考えた。

また、今回採用しているSpring MVCと組み合わせることで、Controllerで処理した結果をViewとしてJSPに渡す構成を取りやすく、画面表示の役割を分けながら実装できる点を採用理由とした。

### HTML / CSS / JavaScript

画面側は、HTML・CSS・JavaScriptの標準機能を中心に構成する。

これらは学習済みの内容であり、今回のシステム規模では追加のフレームワークを導入しなくても、必要な画面表示や操作を実装できると判断した。

そのため、Bootstrapなどの追加フレームワークは使用せず、HTML・CSS・JavaScriptを中心に実装する方針とした。

### Maven

ビルドツールにはMavenを採用した。

`pom.xml` に使用するライブラリや依存関係を明示できるため、プロジェクトで利用している構成を把握しやすいと考えた。

また、Spring Bootとの組み合わせも一般的であり、依存関係とビルド設定をまとめて管理できる点を採用理由とした。

### JUnit 5 / Mockito / Spring Boot Test

テスト環境には、JUnit 5・Mockito・Spring Boot Testを採用した。

単体テスト、依存関係を切り離したテスト、Spring Boot上での動作確認など、テストを行ううえで必要となる基本的な項目を満たせる構成とすることを目的として選定した。

それぞれの役割を使い分けることで、実装内容に応じたテストを行える構成とした。

### Lombok

コードの簡略化と可読性の向上を目的としてLombokを採用した。

getter・setter・コンストラクタなどの定型的なコードを減らすことで、必要な処理に集中しやすくなり、ソースコード全体を読みやすく保てると考えた。

### Bean Validation

バリデーションチェックの記述を簡略化し、可読性を向上させることを目的としてBean Validationを採用した。

アノテーションを利用して入力チェックの条件を定義できるため、バリデーション処理を分かりやすく記述でき、コード全体を整理しやすいと考えた。

### Logback

Spring Bootを利用するうえで、一般的なログ出力の仕組みとしてLogbackを採用した。

Spring Bootとの組み合わせで利用しやすく、アプリケーションの動作状況やエラー内容を確認するための基本的なログ出力を行えるため、採用することとした。

### MySQL Connector/J

データベース接続にJDBCを採用しているため、MySQLとの接続に必要なJDBCドライバとしてMySQL Connector/Jを採用した。

JavaアプリケーションからMySQLへ接続し、Spring JDBCを利用してデータベース処理を行うために必要な構成要素として使用する。

## バージョン選定方針

JDK、Spring Boot、MySQLについては、最新バージョンに近く、かつ安定した利用実績のあるバージョンを選定した。

新しさだけを優先するのではなく、開発時の安定性や情報の入手しやすさも考慮し、ポートフォリオ開発に適したバージョンを採用する方針とした。

## 開発ツール

### Eclipse / MySQL Workbench

EclipseおよびMySQL Workbenchは、学習時に使用していた開発環境・データベース管理ツールであり、操作方法に慣れているため、そのまま本開発でも採用した。

Visual Studio Code、サクラエディタ、draw.ioについては、一般的な閲覧・編集・作図ツールとして使用する。
