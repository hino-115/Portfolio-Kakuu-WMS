# 命名規則

## 1. 目的

本資料は、KAKUU WMSで使用するファイル・フォルダの命名、およびドキュメント内の用語・表記に関する共通ルールを定義する。

## 2. ファイル・フォルダの命名規則

### 2.1 ファイル名

ファイル名は、資料や成果物の内容が判断できる名称とする。

### 2.2 図のファイル名

図のファイル名は、図の内容が判断できる名称、または対応する編集元ファイルが分かる名称とする。

### 2.3 フォルダ名

フォルダ名は、格納する資料・成果物がどのグループに属するか判断できる名称とする。

資料の参照順序が番号によって定まる場合や、前段階の情報を基に成果物を順次作成し、最終成果物へとまとめる場合などは、以下の形式を使用する。

`番号_名称`

なお、すべてのフォルダに番号を付与する必要はない。

### 2.4 共通フォルダ名

以下のフォルダ名を共通で使用する。

| フォルダ名 | 用途 |
|---|---|
| `images/` | 画像の格納 |
| `source/` | `images/` および `delivery/` に該当しない、Markdown以外の成果物の格納 |
| `delivery/` | 顧客に提出する成果物の格納 |

各フォルダは必要に応じて作成する。

## 3. ドキュメント内の表記ルール

### 3.1 業務用語・用語の統一

同じ意味を持つ項目については、可能な限り資料間で表記を統一する。

ただし、用語が初めて登場する箇所や説明が必要な箇所では、別の用語を併記し、同じ意味であることを示してもよい。

例：

`用語A（用語Bと同じ意味）`

### 3.2 ID・コード・番号の使い分け

ドキュメント内で使用する「ID」「コード」「番号」は、原則として以下のように使い分ける。

| 区分 | 用途・意味 |
|---|---|
| ID | システム内部で使用する識別子。ただし、一部例外を認める |
| コード | 業務上の識別に使用するコード |
| 番号 | 業務上の識別に使用する番号 |

「コード」と「番号」は、業務上の識別に用いるという点で同じ意味合いを持つものとし、対象に応じて適切な表記を使用する。

### 3.3 IDの例外

一般的に「ID」という呼称が定着している項目については、システム内部の識別子でなくても「ID」という表記を使用してよい。

例：

- ログインID
- 画面ID
