# 命名規則

## 1. 目的

本資料は、KAKUU WMSで使用するファイル・フォルダの命名、およびドキュメント内の用語・表記に関する共通ルールを定義する。

## 2. ファイル・フォルダの命名規則

### 2.1 ファイル名

ファイル名は、資料や成果物の内容が判断できる名称とする。

### 2.2 図のファイル名

図のファイル名は、図の内容が判断できる名称、または対応する編集元ファイルが分かる名称とする。

### 2.3 フォルダ名

フォルダ名は、格納する資料・成果物がどのグループに属するか判断できる名称とする。

資料の参照順序が番号によって定まる場合や、前段階の情報を基に成果物を順次作成し、最終成果物へとまとめる場合などは、以下の形式を使用する。

`番号_名称`

なお、すべてのフォルダに番号を付与する必要はない。

### 2.4 共通フォルダ名

以下のフォルダ名を共通で使用する。

| フォルダ名 | 用途 |
|---|---|
| `images/` | 画像の格納 |
| `source/` | `images/` および `delivery/` に該当しない、Markdown以外の成果物の格納 |
| `delivery/` | 顧客に提出する成果物の格納 |

各フォルダは必要に応じて作成する。

## 3. ドキュメント内の表記ルール

### 3.1 業務用語・用語の統一

同じ意味を持つ項目については、原則として同一の名称区分内で表記を統一する。異なる名称区分間では、それぞれの目的に適した名称を使用してよい。名称区分および変更時の判断基準は第4章に定める。

ただし、用語が初めて登場する箇所や説明が必要な箇所では、別の用語を併記し、同じ意味であることを示してもよい。

例：

`用語A（用語Bと同じ意味）`

### 3.2 ID・コード・番号の使い分け

ドキュメント内で使用する「ID」「コード」「番号」は、原則として以下のように使い分ける。

| 区分 | 用途・意味 |
|---|---|
| ID | システム内部で使用する識別子。ただし、一部例外を認める |
| コード | 業務上の識別に使用するコード |
| 番号 | 業務上の識別に使用する番号 |

「コード」と「番号」は、業務上の識別に用いるという点で同じ意味合いを持つものとし、対象に応じて適切な表記を使用する。

### 3.3 IDの例外

一般的に「ID」という呼称が定着している項目については、システム内部の識別子でなくても「ID」という表記を使用してよい。

例：

- ログインID
- 画面ID

## 4. 名称区分と名称変更時の判断基準

### 4.1 名称の区分

| 区分 | 名称の種類 | 主な使用箇所 | 例 |
|---|---|---|---|
| A | 業務用語 | 要求分析・要件定義 | 仕入れ、注文、検品 |
| B | 機能名称 | 機能要件・ユースケース・画面要件 | 注文CSV取込、出荷確定 |
| C | 表示名称 | 画面・帳票 | 商品名、注文番号 |
| D | 論理データ名称 | 論理エンティティ・属性定義 | 出荷明細、期限情報 |
| E | 物理データ名称 | テーブル・カラム・実装 | DB命名規則に基づく名称 |

異なる区分間では、同じ情報を扱う場合でも名称の違いを許容する。

### 4.2 名称変更理由の区分

| 区分 | 変更理由 | 上流資料への反映 |
|---|---|---|
| 01 | 誤字・脱字の修正 | 必要 |
| 02 | 同一区分内での表記揺れの解消 | 必要 |
| 03 | 業務上の意味の変更 | 必要 |
| 04 | 機能・実装範囲の変更 | 必要 |
| 05 | 利用者にとっての分かりやすさの改善 | 関連資料のみ |
| 06 | データ設計上の名称の最適化 | 原則不要 |
| 07 | 正規化による分割・統合 | 原則不要 |
| 08 | 物理設計・命名規則への適合 | 不要 |

反映が必要な場合も、変更の影響を受ける資料を対象とする。

### 4.3 適用例

| 変更前 | 変更後 | 変更理由 | 上流資料への反映 |
|---|---|---|---|
| オリコンナンバー | オリコン番号 | 02 | 必要 |
| ユーザーID | ログインID | 03（社員識別情報との区別） | 必要 |
| 期限・入庫日による在庫選定 | 期限・ロット番号による在庫選定 | 03（業務ルール変更） | 必要 |
| 賞味期限 | 期限情報 | 06（属性名称の最適化のみの場合） | 不要 |
| 注文情報 | 出荷 | 06 | 不要 |
| 出荷指示 | ピッキング指示・ピッキング指示明細 | 07 | 不要 |
| CSV取込設定 | CSV取込設定・読み取り設定 | 04・07 | 機能追加部分のみ必要 |

### 4.4 運用方針

- 同一の名称区分内では、原則として名称を統一する。
- 異なる名称区分間では、それぞれの目的に適した名称を使用する。
- 名称変更と業務仕様の変更を区別する。
- 後続工程での名称の最適化やデータ構造の具体化のみを理由として、上流資料の業務用語を変更しない。
- 業務ルール、機能、実装範囲の変更や明確な矛盾がある場合は、影響範囲を確認して関連資料を修正する。
- 異なる名称によって資料間の対応関係が分かりにくくなる場合は、対応関係を明記する。
- 過去の検討・判断記録は原則として維持する。
