# ドキュメント構成ルール

## 1. 目的

KAKUU WMSでは、設計・開発資料を一貫した方法で管理し、GitHub上で成果物の内容および関連資料を確認できるようにする。

本ルールでは、ドキュメントの形式、配置および管理に関する共通方針を定義する。

具体的な工程別フォルダ構成はリポジトリ上の構成を正とし、本ルールには記載しない。ファイル名やフォルダ名の詳細な命名規則は別途定義する。

---

## 2. 成果物フォルダの共通構成

### 2.1 基本方針

- ドキュメントは原則としてMarkdown形式で作成・管理する。
- 図については、draw.ioなどの図作成ツールを使用してよい。
- 図の編集元ファイルと閲覧用画像は分けて保存する。
- 閲覧用画像はMarkdown内から参照し、GitHub上で確認できるようにする。
- Word、Excel、PowerPointなどの資料は、顧客提出用として扱う。

### 2.2 ファイル形式の役割

| ファイル形式 | 役割 |
|---|---|
| Markdown（.md） | ドキュメント本体 |
| draw.io（.drawio）等 | 図の編集元ファイル |
| PNG・SVG等 | Markdownから参照する閲覧用画像 |
| Word（.docx） | 顧客提出用文書 |
| Excel（.xlsx） | 顧客提出用一覧表・設計資料 |
| PowerPoint（.pptx） | 顧客提出用説明資料 |
| PDF（.pdf） | 顧客提出用・配布用資料 |

### 2.3 配置方針

ドキュメント本体は成果物フォルダの直下に配置する。

図の閲覧用画像、図の編集元ファイル、顧客提出用資料は、それぞれ用途別のフォルダに分けて配置する。

以下に共通構成の例を示す。フォルダ名は例示であり、詳細な命名規則は別途定義する。

```text
成果物フォルダ/
├── 成果物.md
├── images/
│   └── 成果物.png
├── source/
│   └── 成果物.drawio
└── delivery/
    ├── 成果物.docx
    └── 成果物.xlsx
```

すべての成果物にこの構成を強制するものではなく、必要なフォルダのみを作成する。

Markdownから図の閲覧用画像を参照する場合は、原則として相対パスを使用する。

記載例：

```markdown
![成果物の図](./images/成果物.png)
```

### 2.4 ドキュメントの正本

Markdown形式の資料を正本とし、顧客提出用資料は正本を基に作成する。

仕様や設計内容を変更する場合は、原則としてMarkdown形式の資料を更新する。図に変更がある場合は、図の編集元ファイルと閲覧用画像の整合性を維持する。

## 3. READMEの配置方針

READMEは、プロジェクト全体の説明、各工程の説明および成果物への案内に使用する。

| 配置場所 | 役割 |
|---|---|
| リポジトリ直下 | プロジェクト全体の説明 |
| 工程フォルダ直下 | 工程の説明・成果物への案内 |
| 成果物フォルダ直下 | 成果物の説明・補足事項 |

成果物フォルダには、必要に応じてREADMEを配置する。

READMEから関連資料を参照する場合は、原則として相対パスを使用する。

---

## 4. 過去版・一時ファイルの管理

### 4.1 過去版の管理

ドキュメントの過去版はGitのコミット履歴で管理する。

過去版を保存するためだけの `old` フォルダは原則として作成しない。

### 4.2 中間成果物の管理

設計過程そのものを説明するために必要な中間成果物は、過去版とは区別して保存してよい。

### 4.3 一時ファイルの管理

Officeの一時ファイルなど、成果物として管理する必要がない一時ファイルはGit管理の対象外とする。

### 4.4 空フォルダの管理

空フォルダをGitで管理する必要がある場合は、`.gitkeep` を使用する。
