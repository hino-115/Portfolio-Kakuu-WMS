# KAKUU WMS 論理エンティティキー設計

## 1. 目的・位置付け

Issue #63の決定事項を整理する。Issue #61の正規化結果およびIssue #62の属性定義を基に、主キー、外部キー、一意性、必須・任意、削除時の参照整合性を定義する。物理的な制約の実装方法は後続工程で定義する。

関連資料：[論理エンティティ属性定義](../03_属性定義/論理エンティティ属性定義.md)、[論理エンティティ正規化](../02_正規化/論理エンティティ正規化.md)、[機能要件](../../../02_要件定義/04_機能要件/機能要件.md)。

## 2. 共通設計方針

- 原則として代理キーを採用する。商品カテゴリは自然キーを採用する。
- 代理キーのIDは自動採番（連番）とし、変更・再利用を禁止する。欠番を許容する。
- 業務上のコード・番号はIDと区別して保持する。
- 通常参照は参照先の主キーと同じ名称・値を保持する。履歴保持用の参照属性は別途定義する。
- PKは論理削除済みを含む全データで一意かつNULL不可とする。

## 6. 必須・任意の定義

PK、一意性対象属性（原則）、ID保持属性、参照系スナップショット、登録者・更新者は必須とする。通常参照はオリコンの棚段IDのみ任意（NULL可）とし、その他は必須とする。FKなしの必須属性は値の存在を要求するが、参照先レコードの永続的な存在は要求しない。

| オリコン内の在庫 | 棚段IDがNULL | 棚段IDあり |
| --- | --- | --- |
| なし | 許容 | 不可 |
| あり | 許容 | 許容 |

棚段未割当のまま入庫実績を登録すること、および棚段未割当在庫への本引当は許容しない。商品・SKUの推奨棚範囲はFKとしない。一般属性の必須・任意は属性定義に従う。

### 7.3 登録者・更新者

全25エンティティの登録者とCSV取込結果を除く24エンティティの更新者（計49属性）に社員IDを保持する。属性名は変更しない。必須、FKなしとする。登録・更新時に社員の存在を保証し、社員の物理削除後もIDを維持する。新規登録時は登録者と更新者に同じ値を設定し、更新・論理削除時は更新者を更新する。登録者は維持する。

## 8. 削除方針・参照整合性

### 8.1 共通方針

- 通常参照のFK値は論理削除後も維持する。論理削除済みの参照元を含め、FK参照が残る間は参照先の物理削除を禁止する。
- 物理削除は依存する子から親の順とし、FKによるCASCADE・SET NULLは採用しない。
- 業務データの論理削除は原則として連動させず、既存の業務ルールに基づく取消処理を行う。
- FKなしのID保持・スナップショットは参照先削除に伴う自動削除・更新を行わない。

### 8.2 マスタ系

| 対象 | 削除方針 |
| --- | --- |
| 商品カテゴリ | 論理削除されていない商品から参照中は論理削除不可 |
| 商品 | SKUを連動論理削除 |
| 会社 | 会社別名・CSV取込設定を連動論理削除。未完了の入荷・入庫がある場合は削除不可。入荷予定は連動削除しない |
| ロケーション | 棚段を連動論理削除 |
| 棚段 | オリコン割当中は削除不可 |
| オリコン | 棚段割当を解除してから削除 |
| 読み取り設定 | 原則物理削除。CSV取込設定から参照中は削除・読み取り種別変更不可 |

連動論理削除は有効・無効を問わず論理削除されていない子を対象とする。削除済みの子は変更しない。削除不可の子がある場合は全体を中止し、同一トランザクションで処理する。個別の業務上の削除条件は既存要件を優先する。

### 8.3 業務データ

- 入荷予定の取消はFR-019に従う。出荷データの削除はFR-047に従う。
- 本引当取消はFR-054に従い、未確定検品、ピッキング指示明細、本引当情報の依存順で論理削除する。検品結果登録後の取消・巻戻しは対象外とする。
- 仮引当情報は再計算時、本引当作成成功時、削除操作時に対象データを物理削除する（FR-050、FR-052、FR-053）。
- 在庫数量0による在庫物理削除時（FR-034、FR-035）は、対象在庫を参照する全仮引当情報を先に物理削除し、在庫を物理削除してオリコンの棚段割当を解除する。同一トランザクションで処理する。仮引当情報の在庫IDのFKは維持する。
- CSV取込結果は保持期間経過後に参照の有無にかかわらず物理削除する。入荷予定・出荷のCSV取込結果IDは維持する（FR-017、FR-043）。
- 確定済み出荷数量の集計元は出荷明細が残る間保持する。検品結果登録に伴う本引当の論理削除と取消による論理削除はデータ状態で区別する。

### 8.4 実装範囲

業務処理に直接伴う論理削除・物理削除は実装対象とする。保持期間経過後の物理削除は保持期間・削除条件・削除方法を設計対象とし、削除処理の実装は対象外とする。

## 9. 正規化結果との整合性

商品・商品カテゴリ、ロケーション・棚段、入荷予定・入荷予定明細、出荷・出荷明細、ピッキング指示・ピッキング指示明細の5件の分割結果を維持する。正規化資料は設計過程の記録として維持する。

在庫のSKUIDはロットIDから取得可能だが、意図的な非正規化として保持する。在庫のSKUIDとロットのSKUIDの一致を保証する。スナップショットは履歴保持を目的として保持する。本確認は全エンティティの第三正規形への到達を保証するものではない。
