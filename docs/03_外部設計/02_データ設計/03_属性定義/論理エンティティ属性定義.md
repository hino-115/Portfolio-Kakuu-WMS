# KAKUU WMS 論理エンティティ属性定義

## 1. 目的・位置付け

Issue #62における個別属性確認および全体整合性確認の決定事項を整理する。属性の必要性と意味を定義し、主キー・外部キー等はIssue #63へ引き継ぐ。未決定の必須・任意や値の範囲は要確認と明記する。

## 2. 共通方針

- 共通管理項目はデータ状態、登録日時、登録者、更新日時、更新者。CSV取込結果のみ登録日時・登録者を保持する。
- 新規登録時は更新日時・更新者に登録日時・登録者と同じ値を設定する。更新・論理削除時は更新日時・更新者を更新し、登録日時・登録者を維持する。共通管理項目はNULL不可。
- 時刻情報はタイムスタンプ、業務上の日付のみの情報は日付型を想定する。物理型は後続工程で定義する。
- ID・コード・番号の現名称を維持し、採否、PK・FK、一意性、参照属性の名称統一は#63で整理する。
- 読み取り設定を新設し、引当情報を仮引当情報・本引当情報に分割する。操作履歴・エラーログはDBエンティティから除外する。操作履歴は実装対象外、システムエラーは外部出力のみとする。
- 確定済みの出荷数量集計元は出荷明細が残る間保持する。検品確定前の取消は検品、ピッキング明細、本引当の依存順で論理削除し、所定期間後の物理削除も依存順を考慮する。
